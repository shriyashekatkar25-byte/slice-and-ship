01 · The decision

What default part size should the uploader use?

If I were the PM shipping multipart uploads in the SDKs and CLI, I'd have to pick the part size people get when they don't choose one. Small parts mean thousands of requests and per-part overhead. Big parts mean each network hiccup throws away more bytes and makes a whole-file failure more likely. The part failure rate is only known from a short Beta, so I treat it as uncertain and let a Bayesian posterior carry that uncertainty into the decision.

Customer problem

“My 80 GB model checkpoint upload died at 97%.”

An ML engineer pushes checkpoints and video datasets into a volume from a laptop on hotel Wi-Fi or from a CI runner. Before multipart, one dropped connection meant starting over. Now the file is split into parts that retry on their own, but only if the part size fits the network.

Proposed change

Ship one evidence-based default

Set a default part size in the SDKs and CLI (still overridable), with 8 parallel streams and up to 3 retries per part. Re-check the default as telemetry piles up.

Success metric

p90 time to upload an 80 GB file

Taken across the posterior, so it reflects our uncertainty about the network, not one lucky guess. Lower is better.

Guardrails
Chance the whole upload fails (p90)≤ 0.1%
Bytes re-sent by retries≤ 3%
Client memory (part × streams)≤ 2 GiB
Parts per file≤ 10,000

04 · The math

The math, from my Monte Carlo course

Frequentist vs Bayesian. A frequentist treats the failure rate q as one fixed number and estimates it with k/n. With only 28 failures in a short Beta, that number is shaky, and plugging it in as if it were exact hides the risk. A Bayesian gives q a distribution: a prior for what we believed before, updated by the data.

prior q ~ Beta(a, b)
data k failures in n ~ Binomial(n, q)
posterior q | k ~ Beta(a + k, b + n − k)
post. mean = w·(a/(a+b)) + (1−w)·(k/n), w = (a+b)/(a+b+n)

Product example. The posterior mean is a weighted average of the prior mean and the Beta's raw rate, with weights set by how much evidence each side holds. A strong prior from earlier upload features pulls a noisy Beta toward history, and as real telemetry grows it takes over. With a flat prior, the peak of the posterior (MAP) equals the raw rate (MLE).

Monte Carlo on top. Upload time and failure risk are messy functions of q. So I draw q from the posterior thousands of times, push each draw through the upload model, and read off p50, p90 and a 95% credible interval from the samples. I use quantile intervals here; a highest-posterior-density interval would be slightly narrower for a skewed Beta.

05 · Real data

How I'd run it on real data

SQL · Beta evidence per network profile

-- illustrative table names
WITH parts AS (
  SELECT client_kind,                  -- 'cli' | 'python-sdk' | 'ci-runner'
         upload_id,
         part_bytes,
         attempt,
         status                        -- 'OK' | 'RETRYABLE_ERROR'
  FROM main.storage_ops.multipart_part_attempts
  WHERE event_date >= date_sub(current_date(), 14)
)
SELECT client_kind,
       sum(part_bytes) / power(2, 28)            AS stretches_256mib,
       count_if(status = 'RETRYABLE_ERROR')     AS failures,
       failures / stretches_256mib               AS raw_rate,
       approx_percentile(part_bytes, 0.5) / power(2, 20) AS median_part_mib
FROM parts
GROUP BY client_kind;

Python · posterior Monte Carlo

import numpy as np
rng = np.random.default_rng(102)

def best_part_size(k, n, prior_mean=0.012, prior_n=400,
                   file_gb=80, bw=40, streams=8, retries=3):
    a = prior_mean * prior_n + k
    b = (1 - prior_mean) * prior_n + (n - k)
    q = rng.beta(a, b, size=4_000)          # posterior draws
    rows = []
    for s in [16, 32, 64, 128, 256, 512, 1024, 2048, 4096]:
        f = 1 - (1 - q) ** (s / 256)        # part fails
        parts = np.ceil(file_gb * 1024 / s)
        tries = (1 - f ** (retries + 1)) / (1 - f)
        secs = parts * tries * (0.35 + s / bw) / streams
        p_fail = 1 - (1 - f ** (retries + 1)) ** parts
        rows.append((s, np.quantile(secs, .9),
                     np.quantile(p_fail, .9), (tries - 1).mean()))
    ok = [r for r in rows if r[2] <= 1e-3 and r[3] <= .03
          and r[0] * streams <= 2048]
    return min(ok, key=lambda r: r[1])
